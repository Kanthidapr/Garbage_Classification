# Garbage Classification — CNN

## 1. ภาพรวมโครงงาน (Project Overview)

โครงงานนี้พัฒนาแบบจำลอง Machine Learning ประเภท Image Classification เพื่อจำแนกประเภทขยะจากภาพ โดยใช้ Convolutional Neural Network (CNN) และชุดข้อมูลจาก Kaggle `mostafaabla/garbage-classification` พร้อมพัฒนาเว็บแอปพลิเคชันด้วย FastAPI เพื่อให้ผู้ใช้ส่งภาพและดูผลการทำนายผ่านหน้าเว็บได้

ปัญหาหลักของโครงงานคือ

> เราสามารถใช้แบบจำลอง CNN เรียนรู้ลักษณะจากภาพขยะ เพื่อทำนายได้ว่าภาพที่ผู้ใช้อัปโหลดอยู่ในประเภทขยะใด

แบบจำลองรับภาพเป็นข้อมูลนำเข้า และส่งผลลัพธ์เป็นชื่อคลาสที่คาดการณ์ พร้อมค่าความมั่นใจ (confidence) ของการทำนาย

## 2. ตัวแปรเป้าหมาย (Target Variable)

ตัวแปรเป้าหมายของแบบจำลองคือ **ประเภทขยะ (Garbage Class)** ซึ่งกำหนดจากชื่อโฟลเดอร์ที่เก็บภาพใน Dataset โดยระบบอ่านชื่อคลาสจากข้อมูลจริงที่ดาวน์โหลด ไม่ควรสมมติว่าชื่อหรือจำนวนคลาสจะตรงกันเสมอโดยไม่ตรวจสอบ Dataset

Dataset `mostafaabla/garbage-classification` มีโฟลเดอร์คลาส เช่น `battery`, `biological`, `brown-glass`, `cardboard`, `clothes`, `green-glass`, `metal`, `paper`, `plastic`, `shoes`, `trash` และ `white-glass` ทั้งนี้ให้ยึดโฟลเดอร์ที่พบจริงจากชุดข้อมูลที่ดาวน์โหลด

ผลลัพธ์ของโมเดลเป็นการจำแนกประเภท (categorical label) ไม่ใช่ค่าตัวเลขต่อเนื่องแบบ Regression

สรุปการทำงานของแบบจำลอง

- ข้อมูลนำเข้า: ภาพขยะ
- แบบจำลอง: CNN ที่ผ่านการฝึก
- ผลลัพธ์: คลาสขยะที่ทำนายได้และค่า confidence

## 3. ตัวแปรนำเข้า (Input Variables)

แบบจำลองใช้ภาพเป็นข้อมูลนำเข้า โดยมีองค์ประกอบสำคัญดังนี้

| ข้อมูล | ความหมาย |
|---|---|
| Image pixels | ค่าสีของแต่ละพิกเซลในภาพ |
| Image height/width | ขนาดภาพที่ปรับให้อยู่ในขนาดมาตรฐานก่อนเข้าโมเดล |
| RGB channels | ช่องสีแดง เขียว และน้ำเงินของภาพ |
| Class label | ป้ายกำกับจากชื่อโฟลเดอร์ ใช้เป็นคำตอบระหว่างฝึก ไม่ใช่ข้อมูลที่ป้อนเข้าโมเดลตอนทำนาย |

โค้ดในโปรเจกต์กำหนดขนาดภาพเริ่มต้นเป็น `64 × 64` พิกเซล และปรับค่าพิกเซลให้อยู่ในช่วง `0–1` ก่อนนำเข้า CNN หากเปลี่ยนขนาดภาพ ต้องปรับการตั้งค่าของโมเดลและ `app.py` ให้ตรงกัน โดยใช้ค่าที่บันทึกไว้ใน metadata

## 4. ข้อมูลที่ไม่นำมาใช้เป็นคุณลักษณะ (Excluded Information)

การจำแนกภาพใช้ข้อมูลพิกเซลจากภาพเป็นหลัก จึงไม่ควรใช้ข้อมูลที่ไม่เกี่ยวกับเนื้อหาภาพเป็นคุณลักษณะของโมเดลโดยตรง

- **ชื่อไฟล์ภาพ**: เป็นตัวระบุไฟล์ ไม่ใช่คุณลักษณะภาพที่ต้องการให้โมเดลเรียนรู้
- **ตำแหน่งไฟล์หรือ path**: ใช้ค้นหาและโหลดภาพเท่านั้น ไม่ใช่ข้อมูลนำเข้าโมเดล
- **ชื่อโฟลเดอร์คลาส**: ใช้สร้าง label สำหรับการฝึกและประเมินผล แต่ไม่ป้อนชื่อคลาสจริงเข้าโมเดลตอนทำนาย
- **ข้อมูลซ้ำหรือภาพที่ไม่ถูกต้อง**: ควรตรวจสอบเพื่อลดผลกระทบต่อการประเมิน หากพบใน Dataset

การแยกข้อมูลและการประเมินต้องป้องกันไม่ให้ภาพเดียวกันหรือภาพซ้ำที่มีความใกล้เคียงกันมากรั่วไหลระหว่างชุดฝึกและชุดทดสอบเท่าที่โครงสร้างข้อมูลเอื้ออำนวย

## 5. การเตรียมข้อมูล (Data Preprocessing)

กระบวนการเตรียมข้อมูลประกอบด้วยขั้นตอนหลักต่อไปนี้

1. ดาวน์โหลด Dataset ผ่าน `kagglehub.dataset_download("mostafaabla/garbage-classification")`
2. ค้นหาโฟลเดอร์ที่เก็บภาพและโฟลเดอร์ย่อยของแต่ละคลาส
3. รวบรวม path ของภาพที่รองรับ เช่น `.jpg`, `.jpeg`, `.png`, `.bmp` และ `.webp`
4. สร้าง label จากชื่อโฟลเดอร์ของแต่ละภาพ
5. ตรวจสอบจำนวนภาพในแต่ละคลาสและข้อมูลที่ไม่สามารถอ่านได้
6. แบ่งข้อมูลเป็นชุดฝึกและชุดทดสอบในสัดส่วน 80:20 โดยใช้ stratified split
7. กำหนด `random_state=42` เพื่อให้สามารถแบ่งข้อมูลซ้ำได้
8. ปรับขนาดภาพเป็น `64 × 64` และแปลงภาพให้อยู่ในรูปแบบที่ CNN รับได้
9. Normalize ค่าพิกเซลให้อยู่ในช่วง `0–1`
10. ใช้ชุดฝึกสำหรับฝึกโมเดล และเก็บชุดทดสอบไว้ประเมินโมเดลหลังฝึก

สัดส่วนการแบ่งข้อมูลที่กำหนดไว้คือ

- ชุดฝึก (Training Set): 80%
- ชุดทดสอบ (Testing Set): 20%

การแบ่งข้อมูลเกิดจากรายการ path ของภาพ ไม่จำเป็นต้องคัดลอกไฟล์ภาพไปสร้างโฟลเดอร์ train/test ใหม่ ควรใช้การแบ่งข้อมูลแบบเดียวกันใน `train.py` และ `test.py` เพื่อให้การประเมินสอดคล้องกัน

## 6. การสำรวจข้อมูล (Exploratory Data Analysis: EDA)

การสำรวจข้อมูลช่วยให้เข้าใจลักษณะและความสมดุลของ Dataset ก่อนฝึกโมเดล โดยประกอบด้วย

- ตรวจสอบจำนวนภาพทั้งหมดและจำนวนภาพในแต่ละคลาส
- ตรวจสอบจำนวนภาพใน Training Set และ Testing Set
- สร้างกราฟการกระจายจำนวนภาพของแต่ละคลาส
- ตรวจสอบภาพที่เปิดอ่านไม่ได้หรือมีรูปแบบไฟล์ที่ไม่รองรับ
- แสดงตัวอย่างภาพพร้อม label เพื่อยืนยันว่าจัดคลาสถูกต้อง
- ตรวจสอบความไม่สมดุลของจำนวนภาพในแต่ละคลาส

ไฟล์สรุปและกราฟที่สร้างโดยโค้ดจะถูกจัดเก็บใน `outputs/` เช่น `dataset_summary.csv` และ `class_distribution.png` หากมีการสร้างไฟล์เหล่านี้จากสคริปต์ที่ใช้จริง

## 7. แบบจำลอง Classification ที่ใช้

### 7.1 Convolutional Neural Network (CNN)

CNN เป็นแบบจำลองหลักของโครงงานสำหรับเรียนรู้รูปแบบเชิงพื้นที่ในภาพ เช่น ขอบ รูปร่าง พื้นผิว และองค์ประกอบของวัตถุ

โครงสร้าง CNN ในโปรเจกต์ประกอบด้วยชั้นหลัก เช่น

- **Convolution**: เรียนรู้ลักษณะสำคัญจากภาพ
- **Max Pooling**: ลดขนาด feature maps และช่วยสรุปลักษณะเด่น
- **Flatten**: แปลง feature maps ให้เป็นเวกเตอร์
- **Dense**: รวมคุณลักษณะที่เรียนรู้เพื่อจำแนกคลาส
- **Dropout**: ช่วยลดโอกาสเกิด overfitting ระหว่างฝึก

### 7.2 กระบวนการฝึกโมเดล

- ใช้ Adam optimizer ในการปรับน้ำหนักโมเดล
- ใช้ Sparse Categorical Cross-Entropy เป็น loss function สำหรับ label ที่เข้ารหัสเป็นตัวเลข
- แบ่งข้อมูล validation จากชุดฝึกตามที่กำหนดในโค้ด
- ใช้ Early Stopping และ Model Checkpoint หากเปิดใช้งานใน `train.py`
- บันทึกโมเดลที่ฝึกแล้วเป็นไฟล์ `.keras`

การตั้งค่า เช่น `EPOCHS`, `BATCH_SIZE` และ `IMAGE_SIZE` ควรยึดตามค่าที่กำหนดในโค้ดที่ใช้รันจริง

## 8. การประเมินแบบจำลอง (Evaluation Metrics)

ใช้ตัวชี้วัดสำหรับงาน Classification เพื่อประเมินความสามารถในการจำแนกภาพ

### 8.1 Accuracy

สัดส่วนของจำนวนตัวอย่างที่ทำนายถูกต้องต่อจำนวนตัวอย่างทั้งหมด

- ค่ายิ่งสูงโดยทั่วไปยิ่งดี
- อาจทำให้เข้าใจประสิทธิภาพคลาดเคลื่อนหากจำนวนภาพแต่ละคลาสไม่สมดุล

### 8.2 Precision

สัดส่วนของตัวอย่างที่โมเดลทำนายว่าเป็นคลาสหนึ่งแล้วเป็นคลาสนั้นจริง

- Precision สูงหมายถึงการทำนายคลาสนั้นมีสัดส่วนผลบวกลวงน้อยลง
- ควรพิจารณาแยกตามคลาส

### 8.3 Recall

สัดส่วนของตัวอย่างในคลาสจริงที่โมเดลสามารถทำนายพบได้ถูกต้อง

- Recall สูงหมายถึงโมเดลสามารถค้นหาตัวอย่างจริงของคลาสนั้นได้มาก
- ควรพิจารณาแยกตามคลาส

### 8.4 F1-score

ค่าเฉลี่ยฮาร์มอนิกของ Precision และ Recall ใช้สรุปสมดุลระหว่างตัวชี้วัดทั้งสอง

### 8.5 Loss

ค่าความสูญเสียที่ใช้วัดความแตกต่างระหว่างผลทำนายของโมเดลกับ label จริง ค่าต่ำลงมักแสดงว่าโมเดลเข้ากับข้อมูลได้ดีขึ้น แต่ควรพิจารณาร่วมกับ validation/test metrics เพื่อเฝ้าระวัง overfitting

ควรรายงานค่า Test Accuracy, Precision, Recall, F1-score และ Support จากชุดทดสอบที่ไม่ได้ใช้ในการฝึกหรือปรับพารามิเตอร์

## 9. การเลือกแบบจำลอง (Model Selection)

การเลือกโมเดลและการตั้งค่าควรพิจารณาจากผลบน validation set ระหว่างการพัฒนา โดยใช้ชุดทดสอบสำหรับประเมินขั้นสุดท้าย

แนวทางการพิจารณาประกอบด้วย

- เปรียบเทียบ Training Accuracy กับ Validation Accuracy
- เปรียบเทียบ Training Loss กับ Validation Loss
- พิจารณา Precision, Recall และ F1-score รายคลาส
- ตรวจสอบว่ามีคลาสใดที่โมเดลทำนายผิดบ่อย
- พิจารณาเวลาในการฝึก ขนาดโมเดล และความเร็วในการทำนายเมื่อนำไปใช้งานจริง

หากมีการทดลองหลายชุดค่าหรือหลายสถาปัตยกรรม ควรบันทึกผลแต่ละครั้งและเลือกโดยอิง validation set ไม่ควรเลือกโมเดลจากผล test set ซ้ำ ๆ เพราะอาจทำให้เกิดการปรับเข้ากับชุดทดสอบ

## 10. การวิเคราะห์ข้อผิดพลาด (Error Analysis)

การวิเคราะห์ข้อผิดพลาดช่วยให้เข้าใจว่าภาพประเภทใดที่โมเดลยังจำแนกได้ไม่ดี โดยสามารถพิจารณา

- Confusion Matrix เพื่อดูคู่คลาสที่โมเดลสับสนกัน
- ภาพที่ทำนายผิด พร้อมคลาสจริงและคลาสที่ทำนาย
- ค่า confidence ของตัวอย่างที่ทำนายผิด
- คลาสที่มี Precision, Recall หรือ F1-score ต่ำ
- ลักษณะของภาพ เช่น แสง มุมถ่าย ฉากหลัง ขนาดวัตถุ และวัตถุหลายชนิดในภาพ

ไฟล์ผลลัพธ์ที่เกี่ยวข้องอาจประกอบด้วย

- `outputs/confusion_matrix.png`
- `outputs/test_predictions.csv`
- `outputs/classification_report.csv`

ให้ใช้ชื่อไฟล์ตามที่สคริปต์จริงสร้างขึ้น หากชื่อหรือรูปแบบ output ในโค้ดแตกต่างจากรายการข้างต้น

## 11. การวิเคราะห์ความสำคัญของคุณลักษณะ (Feature Analysis)

CNN เรียนรู้คุณลักษณะของภาพจากพิกเซลผ่าน convolution layers โดยอัตโนมัติ จึงไม่ได้มีตาราง Feature Importance แบบเดียวกับโมเดลต้นไม้โดยตรง

การทำความเข้าใจสิ่งที่โมเดลเรียนรู้สามารถเริ่มจาก

- ตรวจสอบภาพที่จำแนกถูกและผิด
- เปรียบเทียบผลลัพธ์แยกตามคลาส
- วิเคราะห์ Confusion Matrix
- ใช้เทคนิคอธิบายโมเดลภาพ เช่น saliency map หรือ Grad-CAM หากมีการเพิ่มส่วนนี้ในภายหลัง

ไม่ควรสรุปว่าโมเดลใช้ลักษณะใดเป็นเหตุผลในการทำนาย หากไม่มีการวิเคราะห์หรือ visualization ที่รองรับข้อสรุปนั้น

## 12. การบันทึกแบบจำลอง (Model Saving)

`model/trash_class_cnn_mvp.keras`

ไฟล์ metadata อยู่ที่

`model/metadata.json`

โดย metadata ควรเก็บข้อมูลที่จำเป็นต่อการนำโมเดลกลับมาใช้งาน เช่น รายชื่อคลาส ขนาดภาพ และค่า metric ที่มีการบันทึกจริง

เว็บแอปพลิเคชันจะโหลดโมเดลที่บันทึกไว้เพื่อทำนายภาพใหม่ โดยไม่ต้องฝึกโมเดลใหม่ทุกครั้งที่ผู้ใช้ส่งภาพ

- ค่า confidence ของคลาสที่ทำนาย
- ข้อมูลประกอบเกี่ยวกับโมเดล หาก endpoint ของแอปรองรับ

Endpoint ที่ระบุในโปรเจกต์ ได้แก่

- `GET /` แสดงหน้าเว็บ
- `GET /health` ตรวจสอบสถานะ backend และโมเดล
- `GET /info` แสดงข้อมูลคลาสและรายละเอียดโมเดล
- `POST /predict` รับภาพและส่งผลการจำแนก

ผลลัพธ์เป็นการคาดการณ์จากรูปแบบที่โมเดลเรียนรู้ ไม่รับประกันว่าจำแนกถูกต้องทุกภาพ โดยเฉพาะภาพที่มีหลายประเภทขยะหรือแตกต่างจาก Dataset ที่ใช้ฝึก

## 14. วิธีติดตั้งและเรียกใช้งาน (How to Run)

python -m venv .venv
```

Windows:

.venv\Scripts\activate
```

macOS/Linux:

```bash
source .venv/bin/activate
```

pip install -r requirements.txt

import kagglehub

path = kagglehub.dataset_download("mostafaabla/garbage-classification")

### 14.3 ทดสอบโมเดล

หลังจากฝึกโมเดลแล้ว ให้รัน

## 17. ข้อจำกัดของโครงงาน (Limitations)

1. ประสิทธิภาพขึ้นอยู่กับคุณภาพ ความหลากหลาย และความสมดุลของภาพใน Dataset
2. โมเดลอาจทำนายผิดเมื่อภาพมีแสงน้อย ภาพเบลอ ฉากหลังซับซ้อน หรือมีขยะหลายประเภทในภาพเดียว
3. ผลลัพธ์ขึ้นอยู่กับคลาสที่โมเดลเรียนรู้จาก Dataset หากภาพอยู่นอกคลาสเหล่านั้น โมเดลอาจยังทำนายเป็นหนึ่งในคลาสที่มีอยู่
4. ค่า confidence ไม่ใช่การรับประกันความถูกต้อง และไม่ควรตีความเป็นความน่าจะเป็นที่ผ่านการปรับเทียบแล้ว หากไม่มีการประเมิน calibration
5. ควรประเมินด้วย test set ที่แยกไว้และไม่ใช้ในการปรับพารามิเตอร์
6. ขนาดภาพและ preprocessing ตอน inference ต้องตรงกับตอนฝึก
7. การฝึก CNN อาจใช้เวลาและหน่วยความจำมาก ขึ้นอยู่กับจำนวนภาพและทรัพยากรของเครื่อง

## 18. การ Deploy และลิงก์เว็บแอปพลิเคชัน (Deployment)

โปรเจกต์ออกแบบให้สามารถ deploy เป็น Render Web Service เดียว โดยใช้ FastAPI ให้บริการทั้ง backend และ frontend

ขั้นตอนโดยสรุป

1. ฝึกโมเดลในเครื่องหรือ environment สำหรับฝึก
2. ตรวจสอบว่าได้ไฟล์ `model/trash_class_cnn_mvp.keras` และ `model/metadata.json`
3. Push โค้ดขึ้น GitHub และนำไฟล์โมเดลไปไว้ในตำแหน่งที่ `app.py` คาดหวัง
4. สร้าง Web Service บน Render โดยเชื่อมกับ repository
5. ใช้ Build Command:

```bash
pip install -r requirements.txt
```

6. ใช้ Start Command:

```bash
uvicorn app:app --host 0.0.0.0 --port $PORT
```

7. หลัง deploy ให้ตรวจสอบ `/health` และทดลองอัปโหลดภาพผ่านหน้าเว็บ

ไม่แนะนำให้ Render ดาวน์โหลด Dataset และฝึกโมเดลใหม่ทุกครั้งที่เริ่มบริการ ควรฝึกก่อนแล้ว deploy โมเดลที่บันทึกไว้

ลิงก์เว็บแอปพลิเคชัน: ให้เพิ่ม URL จริงหลัง deploy สำเร็จ
